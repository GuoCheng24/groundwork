# 上手指南 —— 从零到让 agent 替你做科研

写给**完全没用过编码 agent 的人**，并且专门覆盖大多数教程都绕开的那种情况：
**一台连不上外网的共享集群节点**。下面每一个坑都有人真的在上面丢过一整天。

如果你的机器能正常上网，做完第一部分就可以跳到第三部分。

---

## 〇、你真正需要什么

1. **一台能正常上网的笔记本**。
2. **一个账号**。成熟的命令行 agent 有两个：Anthropic 的 **Claude Code** 和
   OpenAI 的 **Codex CLI**。用哪个都行；**两个都有会明显更好**，因为最有价值的
   审查来自一个**没有写过这段东西的模型**。
3. **能 SSH 到放着你数据和 GPU 的地方**。
4. 一个终端。先别用 IDE 面板——它会多出一个你第一天不需要的故障模式（见 2.6）。

全程**不需要 root**，也不往系统目录里装任何东西。

---

## 一、能正常上网的机器

```bash
# Claude Code —— 用官方推荐的原生安装器,会自动更新;
# npm 也能装,但要求 Node.js 22 及以上
curl -fsSL https://claude.ai/install.sh | bash
claude          # 第一次运行会引导你登录

# Codex CLI
npm install -g @openai/codex
codex
```

Codex 没有 npm 也有独立安装包，查它的文档，别为此装一个系统级 Node。

然后在任意项目目录里：

```bash
cd ~/my-project
claude
```

用大白话说你想做什么。它会读你的文件、提出修改、**在执行有后果的命令前问你**。

**第一件事建议让它解释你本来就看得懂的代码**——这是最快校准"该信它多少"的办法。

## 二、连不上外网的集群节点

这是多数高校 HPC 的现状：登录节点也许能出网，计算节点不能，而且你改不了。

### 2.1 思路

笔记本有网，节点有数据。**用反向隧道把连接从笔记本带到节点上**，而且就挂在你
本来就在用的那条 SSH 命令上：

```bash
# 在你【笔记本】的 ~/.ssh/config 里
Host mycluster
    HostName <你本来就在用的地址>
    User <你的用户名>
    RemoteForward 18080 127.0.0.1:1080      # <-- 关键的就是这一行
    ExitOnForwardFailure yes
    ServerAliveInterval 20
    ServerAliveCountMax 3
    TCPKeepAlive yes
```

`RemoteForward 18080 127.0.0.1:1080` 的意思是：**集群发到它自己 18080 端口的东西，
从我笔记本的 1080 端口出去**。后面那个地址指向你笔记本上真正能出网的东西（本地代理
客户端、`127.0.0.1:1080`，随便什么你已经在用的）。前面那个端口随便挑一个没人用的，
它只属于你。

后面那三行 `Alive` / `ExitOnForward` **不是可选项**。没有它们，隧道会在第一次网络
抖动时悄悄死掉，而上层所有东西都会报一个**看起来完全是别的毛病**的错。

### 2.2 让节点用上它

在**集群**的 `~/.bashrc` 里：

```bash
# 隧道真的活着才设代理
if timeout 1 bash -c ': < /dev/tcp/127.0.0.1/18080' 2>/dev/null; then
    export http_proxy=http://127.0.0.1:18080
    export https_proxy=$http_proxy
    export no_proxy=localhost,127.0.0.1
else
    echo "隧道断了 —— 下载任何东西之前先重连 ssh"
fi
```

### 2.3 让每个人都丢过一天的那个坑

> **`git clone` 卡死的真凶通常是 `no_proxy`。**

很多站点级配置会把 `github.com` 放进 `no_proxy`，理由是内网有镜像。在一台没有直连
出口的节点上，这意味着 git **绕开了唯一能用的那条路**，然后卡在一个永远不会打开的
socket 上。报错写着 "connection timed out"，听起来像是代理坏了。**代理没坏，它根本
没被用到。**

```bash
# 某个"本来应该能用"的东西卡住时，逐条强制
no_proxy="" NO_PROXY="" git clone <url>
no_proxy="" NO_PROXY="" gh api repos/<owner>/<repo>
```

下任何结论之前，先 `echo $no_proxy` 看一眼自己的。

### 2.4 一个端口两种协议，什么时候用哪个

混合模式的代理通常在**同一个端口**上同时讲 HTTP 和 SOCKS：

```bash
curl -x http://127.0.0.1:18080       -L https://example.org      # 一般够用
curl -x socks5h://127.0.0.1:18080    -L https://example.org      # 兜底
```

**域名解析不了的时候用 `socks5h`**。那个 `h` 表示 **DNS 交给远端做**，正好解决
"计算节点的解析器根本不认识外面的主机"这个最常见的情况。好几个看起来完全不可达的
站点，其实只是本地解析不出来。

```bash
# python（需要 PySocks）
proxies = {"http": "socks5h://127.0.0.1:18080", "https": "socks5h://127.0.0.1:18080"}
# git，顺便绕开 no_proxy 的排除
no_proxy="" git -c http.proxy=socks5h://127.0.0.1:18080 clone <url>
```

只认 HTTP 代理的工具（好几个下载器都是）必须用 `http://` 那种写法，而且目标域名
**不能**在 `no_proxy` 里。

### 2.5 先验证，再相信

```bash
python -m groundwork reach --targets github.com api.openai.com api.anthropic.com \
                                      pypi.org api.openalex.org arxiv.org
```

看分档，**特别看 `CHALLENGE`**：请求成功了，但正文是一堵机器人墙。任何只看状态码的
东西都会把它当成内容吃下去。返回 `CHALLENGE` 的站点，自动化步骤绝不能消费它的正文。

### 2.6 走隧道时用 CLI，别用 IDE 面板

这些 agent 的图形面板一般维持一条**长连接 WebSocket**，而命令行工具走的是**普通
HTTP 请求**。一条跨越家庭宽带的反向隧道，打断长连接的概率远高于打断一次请求，而且
面板内部的重试上限很低且**你改不了**。

症状：面板里反复报 *"stream disconnected before completion"*，而**同一台机器上终端里
的 CLI 一切正常**。

这个问题**在集群侧无解**。**用 CLI。** 如果 CLI 的重试可配置，就调高——更长的空闲
超时和更多的流重试，能把一个糟糕的晚上变成一个慢一点的晚上。

### 2.7 永远不要在你的私有端口上再起一座桥

如果某个辅助脚本把你的反向转发端口占住了、而占住它的**不是你的隧道**，那么这个端口
对所有幼稚的检查来说都"是开着的"，而所有东西都不工作。排查这个很痛苦，因为每一项
测试都报告"端口在监听"。

两条规矩：

- **"端口开着"不等于"代理能用"**。要用一次真实请求去测；
- 反向转发端口**专用**。它断了就重连 SSH，**不要在上面起别的东西**。

也不要在自己隧道断掉时**静默回退到同事的共享桥**。断了就要响亮地失败。

## 三、第一次会话

```bash
cd ~/my-project
claude            # 或者 codex
```

第一天值得知道的四件事：

- **它先读再写。** 先问"这个仓库是干什么的？"
- **执行前它会问你。** 读一眼它要跑的命令。你能抓到错，也能学到它在想什么。
- **会话内它记得住。** 聊很长没问题，上下文有人替你管。
- **打断是正常的。** 方向不对就直接说，不需要重开。

第一个合适的任务：*"读一下这个脚本，告诉我如果输入文件是空的会怎么崩。"*

## 四、用它走完一整个课题

这是多数教程跳过的部分。**一次只指着一个阶段**，它最强。

| 阶段 | 让它做什么 | 工具 |
|---|---|---|
| 动手之前 | 这台机器到底能做什么，以及**哪些东西装了但不在 `PATH` 上** | `groundwork probe` |
| 决定做不做 | 天花板、**调过参的**平凡基线、随机臂、正对照 | [`groundwork gate`](../groundwork/skills/00-gate/) |
| 查文献 | 谁已经占了这个 claim，以及**你能不能判断** | [`groundwork lit`](../groundwork/skills/10-direction/) |
| 做实验 | 先封印预注册，再摊到空闲 GPU 上跑 | [`prereg`](../groundwork/skills/20-experiment/) · `cluster` |
| 定结论 | 三层互相看不见对方盲区的核查 | [`doubleblind`](https://github.com/GuoCheng24/doubleblind) |
| 写论文 | 先 claim 再散文，图要审，表要生成 | [`40-write`](../groundwork/skills/40-write/) |
| 投稿 | 硬规格写成会失败的脚本；rebuttal | [`50-submit`](../groundwork/skills/50-submit/) |
| 随时，以及推送之前 | 把上面每一道闸门在项目上一次跑完 | `groundwork check` |

最值钱的一个习惯：**先让它做那件"可能直接终结这个课题"的便宜事。** agent 会非常
乐意花你一周去建一个**天花板在第一天就是关着的**东西——不是它不小心，而是**没有
任何东西问过**。

## 五、迟早会咬你的几件事

**长任务会随终端一起死；而"根本没起来"和"正在训练"在启动那一刻长得一模一样。**
后台起，**等 90 秒再相信它**，并读日志开头（配置在那里回显）：

```bash
groundwork watch start --name run1 -- python train.py --epochs 30
groundwork watch status          # 结束时会写下 archive/runs/run1.DONE
```

想手动做也行：`nohup python train.py > run.log 2>&1 &`，然后 `sleep 90`、
`head -20 run.log`，再确认进程还在——但**要用 `ps -p` 去确认，别用发 0 号信号**。
一个**已经退出、但还没被回收的进程**，对 0 号信号的回答和活着时一模一样，于是一个
死掉的任务会被读成健康的。

**日志是空的，几乎从来不是"安静"，而是缓冲。** 输出不是终端时进程会缓冲，于是"正常
跑着"和"什么都没产出"看起来完全一样——而一旦崩溃，缓冲区里的东西全部丢失。用
`PYTHONUNBUFFERED=1` 重起，或者让你的脚本每写一条就 flush。

**会话里设的监听，随会话一起死。** "一小时后帮我看一眼"**不持久**。要写一个**标志
文件**（`watch` 干的就是这件事），并把这个文件名写进项目笔记里当作开工第一件要查的
事。有一次按会话内方式设的监听，**四十小时没人读**。

**断线不会丢上下文。** 这些工具边跑边把对话追加落盘。重连接着聊；进程真死了就用
`--continue` / `--resume` 重建。只丢那一次正在飞的请求。

**配置文件会被两个会话同时写坏。** 如果 agent 行为变怪，先看它的设置文件还是不是
合法 JSON。保持精简。

**装包。** 公共包索引不可达时用镜像：

```bash
pip install -i <你的镜像> <包名>
```

另外**注意 conda 频道**：某些发行版的默认频道**对机构用途并不免费**，而授权跟着你
**下载自哪个仓库**走，不是跟着域名走——**一个受限频道的镜像仍然是那个受限频道**。
社区频道和公共包索引是安全的。

**"没装"通常其实是"不在 `PATH` 上"。** 这台机器上 `which soffice` 返回空了好几周，
而 LibreOffice 一直躺在共享盘**八层目录**之下；那段时间文档一直用一个近似渲染器在
核验，而它会**低估**文字溢出。在集群上，下结论之前先问**软件目录**——`module avail`；
还要记得：一次**跑超时的**文件系统搜索是**没搜完**，不是"不存在"。
`groundwork probe` 会把这几件事都做了，并且明确告诉你哪句是哪句。

**环境是个静默变量。** 产生结果的版本号要**从运行时读出来记下**，别凭记忆——见
[`../skills/20-experiment/hardware.md`](../groundwork/skills/20-experiment/hardware.md)：
同样的权重、同样的随机种子、贪心解码，**换一张显卡差了 1.48 个点**。

## 六、这台机器不是你一个人的

```bash
groundwork probe                                          # 本节点
groundwork cluster survey --nodes gpu01 gpu02 gpu03       # 其它节点
```

- **绝不写死设备号。** 启动时挑最闲的卡。
- **别为了"礼貌"把小模型默认丢给 CPU。** CPU 也是共享的，而且更慢。
- **`/dev/shm` 就是内存。** dataloader 把它填满，用掉的是 `free` 还在报"可用"的那部分
  RAM。`probe` 会把它的大小和占用和 GPU 一起打出来。
- **不只看显存，要看主机内存**，尤其在起多路并发之前。内核的 OOM killer 报的是
  **最后一个申请内存的进程**，不是占得最多的那个——所以既别看到自己名字就认罪，
  也别因此免责，**去查全节点排行**。
- **留一张卡。** `cluster pick` 默认每个节点留一张空闲卡给别人。
